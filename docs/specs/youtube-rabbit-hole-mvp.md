# YouTube rabbit hole MVP

## Problem Statement

YouTube is a place you fall into, but the walk is a line you cannot see and cannot keep. I want to start from one video, get tightly related next videos chosen by a model from official metadata, and keep that walk as a tree I own. I want invited people to have their own private holes on a site I host on Railway. I want to sell this later, so the app stays inside YouTube's API rules. I do not want a public signup eating the model key.

## Solution

A Railway-hosted web app. An invited user signs in with a magic link, pastes a YouTube URL, and gets a private tree. The first expand prefetches two levels with two children per node. The user focuses one video at a time, sees the rest of the hole as an outline, and opens the video on YouTube. They grow a selected node by two children, up to four. Forks are labeled as this app's, not YouTube's recommendations. Five invitees share a $10/month model key, about $2 each, monthly, no daily drip. I have a second model key with no spend cap. When an invitee's month is used up, new holes and grows fail for them until next month.

## Implementation Decisions

- This spec is the v1 product. Alice has no application code. Implement the app as a new TypeScript repo (Bun), hosted on Railway, not inside this skills repo.
- One domain module owns hole commands: create a hole from a URL, grow a selected node, list holes, get a hole, delete a hole, delete an account. HTTP, HTML, and mail sit outside that module and call it.
- That module talks to ports, not vendors: YouTube metadata, YouTube search, fork model, usage meter, hole store, clock. Swap real adapters in production and fakes in tests.
- Official YouTube Data API v3 only. `videos.list` for public metadata. `search.list` for candidates. No InnerTube, no caption scrape, no third-party transcript vendor.
- Parse common YouTube URL shapes down to a video id before `videos.list`.
- Refuse create when the root's public text is too thin to name a subject. Thin children still fork and are marked thin.
- Prefetch on create: two levels below the root, two children per node. Grow adds two children to the selected node, one level, hard cap of four children on a node.
- Dedup video ids inside one hole. Reuse across different holes is allowed.
- The model names freeform forks, then picks from that node's search hits. Prompts must say: same subject or a related topic, drop a candidate if you cannot name the shared subject in one sentence, write a short fork label and a one-line why. Pages that show those picks must say they are this app's forks, not YouTube search results or recommendations.
- Mid-class chat model (GPT-4o or Claude Sonnet class) for invitees and for the owner.
- Two model API keys. Invitee calls use key A. The owner email uses key B. Provider hard limit $10/month on key A. In-app, stop invitee create/grow at an estimated $9 on key A. Split the pot as about $2 per invitee per calendar month. No daily caps. No rollover. Owner calls on key B have no app-side spend cap.
- Estimate spend from billed token usage on each model call. Persist running totals per invitee per month and a shared key-A total.
- One YouTube API project for everyone, including the owner. Search quota is shared.
- Invite allowlist is a config list of emails plus one owner email. No admin UI, no invite codes.
- Auth is magic-link email. No passwords. No YouTube OAuth. Do not request YouTube user scopes.
- Persist users, magic-link tokens, holes, nodes (parent, video id, fork label, why, thin flag, child order), and usage ledgers. Nodes keep video id as the stable key. Cached YouTube title, thumbnail, and description must be refreshed or deleted after 30 days.
- Account delete wipes that user's holes, tokens, and usage rows as soon as possible and within 7 days.
- UI is a focus pane plus a nested outline sidebar. No canvas graph. No in-app player. Links open YouTube.
- Ship a privacy policy page, a link to YouTube's terms, and YouTube branding beside API-backed titles and thumbnails.
- Railway Hobby is fine. Postgres for store. App sleep is allowed if it does not break magic-link consume.

## Testing Decisions

A good test drives the hole module as a caller would: create, grow, list, get, delete. It asserts on the tree and the errors the user would see. It does not assert on prompt strings, HTTP paths, or how many times a port was called.

The one seam is that hole module. YouTube, the model, the meter, the store, and the clock are fakes at the port. There is no second test layer for ranking internals.

There is no prior art in this repo. Alice has no application tests. When the new app repo exists, these tests live next to that module.

Cover at least: happy create with a two-level prefetch, refuse thin root, thin child still forks, grow leaf, grow to four children, refuse a fifth child, dedup inside a hole, invitee month exhausted, instance $9 stop, owner uncapped on the model key, cannot read another user's hole, delete hole, delete account.

## Out of Scope

Public signup. Stripe and paid plans. Self-host. In-app player or proxied streams. User-edited fork names. Starting from a topic search. Shareable or public hole links. Comments as a model input. Transcripts. InnerTube or any scrape. Admin UI. A drawn graph. A second YouTube API project. Daily usage caps. Mobile-specific layout work beyond the same focus-plus-outline page. Teams or seats.

## Further Notes

Grilled in chat. Last correction: monthly invitee caps only, no per-day limits. If they run out mid-month, they wait.

YouTube killed official related-video search in 2023. This app does not try to recreate YouTube's sidebar. It searches from model-written fork queries and reranks with the model.

Default search quota is about 100 `search.list` calls per day on a new project. A create spends 6 searches (two children, two levels). A grow spends 2. That quota is the other wall besides $10 of model spend.

Test seam to confirm: one hole-service module, ports faked. If you want HTTP as the seam instead, say so before implementation starts.
